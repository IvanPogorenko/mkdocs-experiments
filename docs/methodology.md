# Методика исследования

В этом разделе описывается порядок проведения сравнительного тестирования HTTP-серверов.

## 1. Подготовка среды

Перед проведением экспериментов необходимо:

* подготовить тестовый сервер;
* установить инструмент генерации нагрузки;
* настроить исследуемые конфигурации;
* подготовить единый набор HTTP-запросов;
* проверить доступность тестового приложения.

## 2. Параметры тестирования

Для каждого эксперимента используются следующие параметры:

| Параметр                        | Значение  |
| ------------------------------- | --------- |
| Число виртуальных пользователей | 50        |
| Количество запросов             | 10 000    |
| Тип запросов                    | HTTP GET  |
| Содержание ответов              | JSON      |
| Число повторов                  | 3         |
| Интервал между экспериментами   | 30 секунд |

## 3. Используемые метрики

### Среднее время ответа

Среднее арифметическое времени обработки всех запросов:

$$
T_{\text{avg}} = \frac{1}{N}\sum_{i=1}^{N}t_i
$$

где:

* \(N\) — количество запросов;
* \(t_i\) — время ответа на запрос с номером \(i\).

### Пропускная способность

Количество успешно обработанных запросов за единицу времени:

$$
R = \frac{N_{\text{success}}}{t}
$$

где:

* \(N_{\text{success}}\) — количество успешных запросов;
* \(t\) — продолжительность тестирования в секундах.

### Доля ошибок

Процент запросов, завершившихся ошибкой:

$$
E = \frac{N_{\text{error}}}{N_{\text{total}}}\cdot 100\%
$$

## 4. Порядок проведения

1. Запустить сервер с первой конфигурацией.
2. Выполнить тестовую нагрузку.
3. Сохранить результаты измерений.
4. Повторить тест ещё два раза.
5. Переключить сервер на следующую конфигурацию.
6. Повторить процедуру для всех конфигураций.
7. Рассчитать средние значения метрик.
8. Сравнить полученные результаты.

## 5. Обеспечение достоверности

Для уменьшения влияния внешних факторов необходимо:

* использовать одинаковый набор запросов;
* проводить тестирование в одной среде;
* исключать постороннюю нагрузку;
* выполнять несколько повторов;
* фиксировать версии программного обеспечения;
* сохранять исходные результаты измерений.

## 6. Ограничения

Представленная методика является упрощённой. В реальном исследовании следует учитывать аппаратные характеристики сервера, сетевые задержки, прогрев кэша и распределение времени ответа, включая высокие перцентили.
